# Reading and maintaining the code

Current unmerged UX candidate: [0.2.3-review.1](UX_SIMPLIFICATION.md). Historical behavior below is superseded where stated there.

This guide is intended for a developer new to legacy WoW-style Lua. Start with
the TOC: the client executes its listed files in order. Tests and Python tools
are never in that list. There is no modern module loader or required library.

## Module order and responsibilities

1. **Runtime.lua:** creates FieldKit, validates finite numbers, restricts native
   setting writes and bounds learned-name persistence. No native writes at load.
2. **Config.lua:** defines conservative defaults and repairs persisted data shapes.
   InitializeSettings runs after VARIABLES_LOADED. It never imports MASHDB.
3. **Localization.lua:** addon-label dictionaries, weak widget bindings and live
   refresh callbacks. Native data is not translated or used as executable code.
4. **Seed.lua / PortraitCatalog.lua:** declarative inherited/generated data. The
   seed helps name classification; the catalog links zone/name aliases to known
   native creature/display ids and packaged texture keys.
5. **Portraits.lua:** resolves independent static portraits and reports conflicts.
   Native instance ids identify live entities, not model appearances.
6. **Settings.lua:** small descriptor factories for health, language, minimap and
   privacy controls. The factories keep closure capture low for Lua 5.0.
7. **OptionsSchema.lua:** declarative option pages. Local HUD actions are injected
   in a table; descriptor getters read FieldKitDB only when the UI refreshes.
   Building the schema does not apply options.
8. **LegacyCrits.lua:** the separate optional eight-line critical display. It
   preserves the old max-value-plus-count grouping; this is not a damage total.
9. **FieldKit.lua:** the HUD/controller and native frame adapters. The settings shell lives in Interface.lua.
   Stateful helpers remain local. Its scoped blocks are intentional: flattening
   everything can exceed the old 32-upvalue limit. This module is still large;
   further splits should follow tests and explicit dependency tables, not globals.
10. **WorldPins.lua:** projects native world coordinates to minimap pixels, reuses
    bounded pools and distinguishes exact lair location from moving creatures.
11. **CombatText.lua:** parses bounded events, applies filters, merges and animates
    a fixed slot pool. No real damage is generated by the preview path.
12. **CombatOptions.lua:** the single combat editor; it edits the renderer's DB
    keys and uses preview/drag helpers rather than implementing a second renderer.
13. **CopyLog.lua:** opt-in main-chat memory buffer and user-opened copy editbox.

## Lifecycle and data flow

At chunk load, modules define functions, static data and lightweight event frames.
VARIABLES_LOADED is handled once: normalize FieldKitDB and create the fixed HUD
frame pools. PLAYER_ENTERING_WORLD refreshes visible data and applies explicitly
chosen native visual settings. Combat/unit/inventory events refresh their owners.

The main OnUpdate loop calls plate maintenance and legacy critical animation,
then maintains layout/health/buff/debuff timing at 0.05 seconds. Run snapshots
(money, meters, pins and lairs) refresh every 0.2 seconds, matching the documented
5 Hz delivery limit. Native meter stamps avoid rebuilding unchanged spell rows,
while the native total-DPS getter remains fresh as the run clock advances. The
portrait cache uses the native unit stamp, table identity, frame identity and
UI language; clients without numeric stamps retain the uncached path. The combat renderer checks grouping
and healing at 0.05 seconds while animating active text each frame. Chat's watcher
checks only its option at 0.2 seconds.

The native data path is: **AZS/client observation → validation/projection/format →
addon widget**. The settings path is: **player click/drag → own DB → local UI
refresh or an explicitly listed native visual action**. Network or disk writes
are not part of either path. The client itself persists SavedVariables.

## Legacy Lua rules

- `string.match`/`gmatch` are not available. Use `string.find` captures and gsub.
- Use table.getn / ipairs; keep the shipped syntax executable in Lua 5.0.3.
- Event callbacks consume client globals `this`, `event`, `arg1`, etc. Capture
  loop values in distinct locals before making callbacks, especially tab indices.
- A `local Name` declaration followed by `function Name()` in the same scope is
  a local forward declaration, not a global leak. Do not mechanically rename these.
- Limit nested-function upvalues to 32. Tests inspect **every** nested prototype,
  not just event paths reached by a mock. Current maximum is 23.
- Check optional API methods/functions before use. Unknown CVars may throw;
  use the Runtime wrapper or WorldPins' guarded read.

## Numbers and identity

FieldKit.Number rejects NaN/infinity and unreasonable magnitudes before arithmetic
at the repaired boundaries. Native row shape remains a client contract; do not
describe it as hostile-input isolation. Add tests when introducing new boundaries.

Creature names are localized and may repeat. The portrait catalog includes zone,
entry and display identity; separate live ids retain separate HP/state. Do not
substitute a current target texture for an unresolved boss. Native statistics and
combat-log deltas are not independent totals to add together.

## Where to make common changes

- New option: OptionsSchema or Settings, default/validation in Config, localization
  entries, action injected from FieldKit.lua, then a callback/persistence test.
- New combat category: defs/defaults/parse/filter in CombatText, editor controls
  if needed, translation and event fixtures. Never invent missing events.
- New portrait: prove native identity, update catalog/assets with provenance,
  test duplicate names/conflicts/zone and other-target independence.
- New native write: add it to API_SURFACE and SECURITY, justify approval impact,
  keep it user-driven where appropriate and test missing/invalid inputs.

The [function index](CODE_INDEX.md) links each named function to its declaration.
Anonymous callbacks are documented by their enclosing constructor/schema and the
effects inventory. Generated data is explained at module level rather than by
repeating a comment for each of the 1,063 aliases.

### Presentation layer (0.2)

Theme.lua owns fixed local materials, typography and cached geometry. It skins
only FieldKit-owned surfaces. InterfaceStrings.lua extends EN/FR display labels.
Interface.lua takes existing schema actions, organizes stable journey ids and
constructs the settings/layout dock once. Refresh reads; setters require user
input. CombatOptions.lua contributes the six-page editor and reflows its existing
widgets. Config.lua migrates the legacy page selection without resetting feature
preferences. New UI behavior is covered by tests/interface_journey.lua.

GameCompatibility.lua contains the guarded native Heroic context, exact critical-objective nameplate exception and fractional-bonus formatting. Read docs/GAME_0_121.md and tests/game_0121.lua before extending it. It adds no native setter or gameplay action.

RunMode.lua renders the native rank/zone separately from the labelled 0.121 mechanic reference. HudStack.lua owns only left-card geometry, preserves legacy positions and forwards player drags to the stack anchor. Both are initialized through injected HUD constructors; no native gameplay writer is added. tests/mode_stack.lua validates the actual frame geometry and controls.

Positions.lua validates and persists native point/relative-point offsets. Drag-stop callbacks use this path without GetCenter subtraction. Legacy numeric positions remain a fallback. HudStack.lua now uses a full-size, mouse-disabled clamp proxy; linked cards delegate clamping to it. tests/edge_positions.lua covers zero-inset edges and native-anchor restoration.
