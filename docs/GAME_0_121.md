# Game 0.121.0 compatibility

FieldKit candidate: 0.2.1-review.1. Assessed on 2026-10-27 from the maintainer's
supplied changelog, local addon API document and installed client. No live test
of this candidate, Heroic clear or developer approval is claimed.

## Evidence and limits

The installed executable contains the 0.121.0 version marker and the native
zone-message field `;heroic=`. Its embedded addon bridge assigns parsed zone
messages to `AZS_ZONE` using the generic key/value parser. This provides a basis
for reading `AZS_ZONE.heroic`, guarded for missing/invalid data and active phase.
It does not establish that a particular live session has delivered the field.

The executable also contains the exact native names `Explosive Orb` and
`Orbe explosif`. The addon only preserves existing nameplates for these names;
it does not locate, target, attack or infer an orb spawn. A name-based visibility
exception is not an instance-identity or mechanic-state detector.

Exact input size, SHA-256, marker findings and exposed getter names are recorded
in [client-0.121-evidence.json](client-0.121-evidence.json). The executable
was read, never executed by an analysis script or modified. Raw native code,
resources, game saves and private player data are not included in that record.
The supplied API document predates this update; it does not document Heroic,
marks, stars or active affixes, so it is not treated as a complete new contract.

## Implemented

- Settings context displays **Normal / Heroic I–V** from the native rank only.
  Retained tables outside a run, absent fields and invalid ranks display no rank.
  The zone's `diff` multiplier and old `mods` Run Options never imply a rank.
- Stat bonuses preserve tenths: `+0.3%` stays visible instead of `+0%`.
  Fractional native kill-heal bonuses also retain tenths. Whole values omit `.0`.
  Values remain native current totals, not a locally reconstructed star formula.
- The optional ordinary-mob nameplate filter preserves explosive-orb plates,
  even if learned as normal enemies. The player's V-key state still applies.
- Existing multiple-boss frames support a final boss and earlier companion boss
  independently. A new fixture checks both frames while another enemy is targeted.
- Effective damage, healing, health, boss health and equipment tooltips keep
  using native data. No extra Heroic/co-op scaling or second healing penalty is
  applied. The game resolves stars, set effects, proc damage and Withering.

## Not available as confirmed addon data

No confirmed export was identified for class marks, per-item stars, set unlocks,
bad-luck counters or the currently active weekly affixes. Searches found no
`AZS_GEAR`/`AZS_ARMORY` tables or new getter for these values in the inspected
client. This is an investigation result, **not proof that such data is impossible
to obtain**. FieldKit does not scrape game saves, infer stars from names, claim
an upgraded set bonus, predict drops or guess weekly affixes from the calendar.

The existing accessories window still contains its original five slots. Native
tooltips are authoritative; FieldKit does not claim a full armor/set-progress
tracker. A future supported armory API would allow a separate, accurate view.

Useful questions for the game developers: is there an approved read-only export
for the rank semantics, active affix ids, class mark balance, equipped item ids
and stars, unlocked star caps, and actual 4/8-piece bonus state? Field names must
be supplied/verified before an addon offers that progression display.

## Validation

`tests/game_0121.lua` exercises actual settings context, fractional stat output,
simultaneous boss frames and the real nameplate filter callback chain. It checks
the normal/Heroic distinction, missing/invalid data, phase reset, name exceptions
and V-key behavior under native Lua 5.0.3 and Lua 5.1. Existing HUD, combat,
privacy, appearance and persistence fixtures remain in place.

In game, verify a normal run and an unlocked Heroic run, EN/FR, a small upgraded
bonus against the native character pane, an explosive orb with filtering enabled
and V on/off, and two simultaneous bosses in Heroic V. Check effective healing
against the native healing meter. Tests require the corresponding progression
to be genuinely unlocked; FieldKit never unlocks or changes it.
